Quizey started from a conviction: exams should do more than measure — they should improve learning. It's a backend exam and training platform where teachers create assessments, students take them with integrity, and grading is fast, consistent, and auditable. The product isn't exams — it's continuous, measurable learning improvement. I'm building it production-oriented: copy-on-write versioning, state machines, database-backed idempotency, fail-closed Redis JWT revocation, and audit integrity come before any intelligent feature — all backed by 1,100+ automated tests.

Complete
Phase 1 — Foundation

The core loop works end-to-end: create exams, publish them, take them, get graded. Copy-on-write versioning keeps published exams immutable. JWT auth secures every endpoint. 1,100+ automated tests verify the entire system — including state-machine subtests covering the attempt lifecycle. This is the solid foundation everything else builds on.

FlaskSQLAlchemyJWT AuthCopy-on-Write1,100+ Tests
In progress
Phase 2 — Production Platform

Taking the foundation toward production — the reliability, rich grading, and integrity tooling that real organizations need to trust their assessments. Implemented so far: attempt lifecycle (pause/resume, lazy expiry, telemetry), advanced grading (multi-select partial credit, weighted and bonus questions, manual grading with rubrics), assessment rules, and an integrity layer with database-backed idempotency keys, atomic transactions, immutable audit logging, and Redis-backed JWT revocation with expiration-aware TTLs and fail-closed security behavior during cache outages. Remaining: version management tooling, question banks, dashboards, platform services, and DevOps.

Intelligent question generation, personalized feedback, and adaptive learning paths — built on Phase 2's clean data and stable infrastructure. AI is not implemented in the current backend; it is deliberately planned only after the platform is reliable.
