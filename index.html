Quizey started from a conviction: exams should do more than measure — they should improve learning. It's a backend exam and training platform where teachers create assessments, students take them with integrity, and grading is fast, consistent, and auditable. The product isn't exams — it's continuous, measurable learning improvement. I'm building it production-oriented: versioning, state machines, idempotency, and audit integrity come before any intelligent feature.

Complete
Phase 1 — Foundation

The core loop works end-to-end: create exams, publish them, take them, get graded. Copy-on-write versioning keeps published exams immutable. JWT auth secures every endpoint. 393 tests verify the entire system — including 23 state-machine subtests covering the attempt lifecycle. This is the solid foundation everything else builds on.

FlaskSQLAlchemyJWT AuthCopy-on-Write393 Tests
In progress
Phase 2 — Production Platform

Taking the foundation toward production — the reliability, rich grading, and integrity tooling that real organizations need to trust their assessments. Implemented so far: attempt lifecycle (pause/resume, lazy expiry, telemetry), advanced grading (multi-select partial credit, weighted and bonus questions, manual grading with rubrics), assessment rules, and an integrity layer with idempotency, atomic transactions, and immutable audit logging. Remaining: version management tooling, question banks, dashboards, platform services, and DevOps.

State MachineIdempotencyAudit LogManual GradingRubricsTelemetry
Planned
Phase 3 — AI-Native Learning

Intelligent question generation, personalized feedback, and adaptive learning paths — built on Phase 2's clean data and stable infrastructure. AI is not implemented in the current backend; it is deliberately planned only after the platform is reliable.

My philosophy: build boring before building impressive. The foundation, the data model, the integrity layer — that's what makes the intelligent features valuable later, not the other way around.
